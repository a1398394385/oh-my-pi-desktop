# 代码注释规范（SSOT）

> 适用范围：`host/` `ui-src/` `scripts/` `src-tauri/src/` `ui/` 下全部源码文件的注释。
> 登记见 [documentation.md](documentation.md) §2「代码注释规范」。根 [AGENTS.md](../AGENTS.md) 只留硬约束摘要与指针，本文件是写作、删除与治理的唯一定义。
> 机器门禁：注释语言棘轮 `scripts/check-comment-language.mjs`（`bun run check` 内，基线 `scripts/comment-language-baseline.json` 只许降不许升）。

## 1. 第一原则

**注释只记录代码表达不了的信息。** 代码能表达的（做什么、怎么做、有多少个分支）一律交给代码、命名与类型；注释负责代码里没有的那部分：意图、约束、否决过的方案、外部事实、事故编号。

判定一句话：*删掉这条注释，下一个读者（人或 agent）会不会失去唯一可得的信源？* 会 → 保留；不会 → 删除。

## 2. 允许写的五类信息

1. **为什么（意图）**：为什么这里要这样写、为什么不能换成更直观的写法。
2. **约束与不变量**：调用顺序、线程/事件模型、协议前置条件、性能上限、必须成对出现的操作。
3. **否决过的方案与反例**：试过什么、为什么不行、什么情况下会退回旧方案。
4. **外部事实与坑**：上游 SDK 行为、平台差异、第三方接口怪癖；带版本号或 issue 编号。
5. **事故与回归护栏**：`BUG-NNN` / `RULE-NNN` / ADR 编号，说明这段代码在拦什么回归。

本仓库的真实正例（保留这几条注释是刻意的，不是遗漏）：

- `ui/css/main/center.css` 的列宽把手注释：说明竖线是「140px、两端渐隐、**never a full-height rule**」——挡住"以后顺手改回整条线"的回归。
- `ui/css/main/shell.css` 的 BUG-017 注释：记录"测过，无布局收益，所以不用 content-visibility"，防止下一个 agent 重走已证伪的路。
- `.agents/rules.md` RULE-009 的 Why：记录一次不可逆乱码事故，这是规则存在的唯一理由。

## 3. 禁止写的七类

1. **复述代码**：`// increment i`、`// return the user`、逐行翻译实现。
2. **注释掉的代码**：要留历史用 git；要留方案用 ADR。
3. **无主 TODO / FIXME**：必须带 owner 或工单（`TODO(BUG-123): ...`），否则删除或转 `.agents/BUGS.md`。交付红线：不允许 `TODO: implement` 占位。
4. **与实现不同步的说明**：过时注释是负债，不是历史档案；不一致即缺陷。
5. **行号 / 易漂移路径引用**：改用符号名（`splitBlocks`）、文件名或工单号。
6. **装饰噪声**：ASCII 分隔线、重复标题、emoji；除拓扑图本身必要。
7. **自动生成噪音**：AI 逐行解释、显而易见的 JSDoc 参数复述。

## 4. 写法约定

- **语言**：注释一律英文（开源国际化 + 门禁）。中文只允许出现在 `ui-src/i18n/` 语言包与用户可见文案。
- **位置**：紧贴它约束的代码上方；跨多个函数的约束写文件头。不要放在与它无关的段落里。
- **长度**：单块 ≤ 6 行；超过说明信息该去文档（ADR / `docs/systems/` / `docs/PITFALLS.md`），代码里留一行指针。
- **结构**：首行一句话结论；需要展开时用 `1.` / `-`；术语使用代码里的真实符号名。
- **引用**：`BUG-017`、`RULE-009`、`ADR-0005`、上游 `owner/repo#1234`、SDK 版本号——必须真实存在。
- **风格**：与本文件所在目录既有注释一致；不为了统一风格重排无关注释。

## 5. 删除判据（逐条过）

1. 这条信息能从代码/类型/测试读出吗？→ 能则删。
2. 它在解释"做什么"而不是"为什么"吗？→ 是则删或改写成 why。
3. 它是任何其他文档都没有的唯一记录吗？→ 是则先迁移到 BUGS / PITFALLS / ADR / Spec，再删并留指针。
4. 它与当前代码一致吗？→ 不一致先判定哪边是事实（实测），改一侧，禁止并存矛盾定义。
5. 下一个读者会因此少走一次弯路吗？→ 不会则删。

## 6. 与 AI / agent 协作

- **注释是意图线索，不是事实来源。** agent 的验证优先级：运行结果与测试 > 代码 > 注释。
- 注释与代码冲突时：以代码为准，把不一致当缺陷上报（在改动说明里列出），**禁止照着注释改代码**。
- AI 生成代码时默认不写解释型注释；只有承载 §2 某类信息时才写。
- 注释里不要写"给 AI 看"的指令（prompt 注入面），也不要写无法被机器校验的断言（"性能很好"）。能量化的写数值与测量方法。

## 7. Review checklist（每个改动自查）

- [ ] 每条新增注释都能归入 §2 的五类之一
- [ ] 没有新增无主 TODO/FIXME
- [ ] 改动的代码与相关注释在同一次改动内同步
- [ ] 注释里的符号名 / 命令 / 路径 / 工单号真实存在
- [ ] 删除的注释没有丢失唯一信息；若丢失，已迁移并留下指针
- [ ] `bun run check` 的注释语言棘轮计数未上升

### 8.2 波次

按「先清死代码 → 再处理知识密集区 → 最后机械翻译」排序。每波独立 commit、独立验收，不允许跨波混改。

| 波次 | 范围 | 策略 | 目标产出 |
|---|---|---|---|
| **W0** | 死代码与临时脚本 | **先判死活，不做注释优化** | 删除批（需 owner 确认）：`ui/markdown.js`、`ui/prov-logos.js`、`ui/prototypes/`（全仓无运行引用，仅文档提及）；`scripts/tmp-*.ts`（未跟踪临时脚本）。死文件上的注释一律不优化 |
| **W1** | host 核心：`session-lifecycle.ts`、`assets.ts`、`state.ts`、`rpc/session.ts`、`acp-runtime.ts`、`keepalive.ts`、`translate.ts`、`wire/payloads.ts`、`rpc/*` | **核对 + 精简**：BUG/RULE 引用、协议不变量、上游坑必须逐条留；只删 what 型与重复块。本波以人工为主，禁止批量脚本 | 每文件一份"删除/保留/改写"清单 |
| **W2** | `host/limits/vendor/`（移植代码） | **provenance 优先**：上游原始注释保留，在文件头补来源与移植差异指针；只删本地改写留下的过期说明 | 每个 vendor 目录一行来源声明 |
| **W3** | `ui-src/`：`components/` → `lib/` + `store/` + `types/`（三步小批） | 删解释型注释；保留交互物理、Electron/WebView 差异、React 19 约束（selector/引用语义） | 每小批 diff ≤ 400 行 |
| **W4** | `ui/` 活文件（`icons.js`、`style.css`、`css/`、`themes/`） | 死文件在 W0 已删；活文件只保留 token/级联顺序/图标注册表约束 | 与 `docs/systems/frontend.md` 一致 |
| **W5** | `scripts/`（门禁与冒烟脚本） | 门禁脚本头部的规则解释是 SSOT 的一部分：保留并压缩到 ≤ 10 行块；删除逐行解释 | 每个 check 脚本头部一句话规则说明 |
| **W6** | `src-tauri/src/`（Rust） | 平台差异（Windows tray / 单实例 / macOS 交通灯）保留；删除 what 型 | 平台行为注释带平台版本或 issue |
| **W7** | 中文注释清零 | 按目录分批译英，保留术语与代码符号；每批后 `node scripts/check-comment-language.mjs --update` 收紧基线，最终基线全 0 | 门禁基线 0 |

### 8.3 每波作业 SOP

1. **分支与粒度**：一波一分支；单文件 diff 超过 400 行时拆 commit（按函数/区块）。
2. **只动注释**：不得夹带代码行为、格式化、重排、重命名。发现必须改代码时，另开改动。
3. **迁移优先**：删前自问 §5 第 3 条；唯一信息迁到 `.agents/BUGS.md` / `docs/PITFALLS.md` / `.agents/notes/` / `docs/systems/`，代码里留一行指针。
4. **证据**：删除型改动在 commit message 里写"删除了什么类型、为什么安全"；改写型写"原注释指向的符号已改名"。
5. **复核**：每波抽取 ≥10% 文件由第二人复核，重点看"被删掉却可能是唯一记录"的注释。
6. **禁止**：整文件回写（RULE-009）、`--no-verify`、跨目录混合改动、顺手升级依赖。

### 8.4 验收命令

```bash
node scripts/comment-audit.mjs         # 注释审计：前后对比注释行、中文注释与 TODO
bun run check                        # 注释语言棘轮 / 编码 / i18n / 类型
bun run ui:typecheck                 # ui-src 改动必跑
bun run smoke:features               # host 核心改动抽样冒烟（其余按 host/ 目录对应 smoke）
```

验收标准：
- 每波注释行数下降，且每一处下降都有"删除类型"说明；
- 唯一记录零丢失（抽查 BUG 编号命中数不下降）；
- `bun run check` 全绿（scripts 中文注释项随 W5/W7 收敛）；
- 行为零变化：ui-src 跑 `ui:typecheck` + 相关冒烟，host 跑对应 smoke。

### 8.5 风险与对策

| 风险 | 对策 |
|---|---|
| 注释里藏着唯一的事故/上游坑记录 | W1 起把"含 BUG/RULE/issue 编号"的注释列为不可删清单，先迁移再删 |
| 大文件改写导致 diff 淹没、误改代码 | 只允许"删除/替换注释行"，review 时检查 diff 的 `+`/`-` 行均为注释 |
| 译英引入术语漂移 | 保留真实符号名、命令、路径原样；术语表见 `ui-src/i18n/README.md` 与 `.agents/domain.md` |
| 死代码判定错误 | W0 删除前用全仓引用检索（运行入口 + 构建配置 + 脚本）双人确认 |
| 与进行中的功能分支冲突 | W1/W3 按文件认领，同一文件同一时刻只有一个负责人 |
