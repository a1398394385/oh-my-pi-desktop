# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack
delegated: 单文件静态 HTML + 内联 CSS/JS（用户要求"可互动的完整 HTML 示例"，明确不接真实 omp、不需要框架与构建步骤）

## Users
[推断自 brief] omp（`@oh-my-pi/pi-coding-agent`）的重度使用者，即本示例的作者本人。终端里长期并行跑多个编码会话，需要图形外壳做多任务管理、进度观察与确认决策。场景：macOS 桌面、大屏、长时间驻留、频繁切换。

## Product Purpose
[推断自 brief] 把 omp CLI 的会话能力包成桌面工作台，让"开任务、看进度、给确认、切模型"不再依赖终端输出记忆。成功标准：不读原始日志也能知道每个会话在做什么、卡在哪。

## Positioning
[推断] 状态面板是一等公民：把 agent 的内部进程（进程清单 / 计划 / 目标 / 终端 / 智能体 / 更改 / Git）直接暴露在会话右侧，而不是只显示聊天记录。

## Operating Context
[推断] 工作区 = 本地 git 仓库，一个仓库下多个会话并行；需要频繁切换模型与推理档位；需要处理权限确认与文件变更审查。

## Capabilities and Constraints
本次示例包含：左侧任务/项目导航、会话消息流、底部输入区（@ 提及 / 模式 / 模型 / 推理强度 / 上下文用量）、右侧状态面板（进程 / 计划 / 目标 / 终端 / 智能体 / 更改 / Git）、右侧边栏（辅助对话 / 审查 / 终端 / 浏览器四类标签，可多开）、权限确认卡片、深浅主题、侧栏折叠、命令面板。
明确排除：设置中心全部页面、插件市场、自动化（定时/闲时任务）、Wiki 引用标签、真实 omp 接入。
字体族与字号「可在设置中配置」属套壳需求，已记入 `../docs/zcode-desktop-功能手册.md` §15，本原型不实现。
所有数据为演示用合成数据。

**重要**：原型里的权限模式、模型名、思考级别均为**样式占位**，与 omp 真实值域不同（真实值域见手册 §16）。实现时必须从 omp 读取：模型走 `get_available_models`，思考级别随当前模型的 `thinking` 能力，权限模式只接受 `always-ask | write | yolo`。

## Brand Commitments
无既有品牌资产。功能架构参照 ZCode 桌面端（见 `../docs/zcode-desktop-功能手册.md`），视觉不复制。

## Evidence on Hand
功能清单来自 `../docs/zcode-desktop-功能手册.md`（本机实测 + app.asar 源码提取）；omp 能力来自 `@oh-my-pi/pi-coding-agent` v18.2.5 的类型定义。无真实截图、无品牌素材、无用户证言。

## Product Principles
1. 状态先于内容：任何时刻都能一眼答出"这个会话在做什么、卡在哪"。
2. 熟悉优先：沿用桌面工具既有词汇与控件（侧栏、标签、命令面板），不为新鲜感重新发明。
3. 密度受控：默认为多会话高密度，但层级靠间距与色彩层次建立，不靠边框堆叠。
4. 确认可见：需要用户决策的点必须浮到表面，不埋在日志里。

## Accessibility & Inclusion
[推断] 键盘可达（可见焦点环、Esc 关闭浮层、⌘K 命令面板）；正文与占位符对比度 ≥4.5:1。
