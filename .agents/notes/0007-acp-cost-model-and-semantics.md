## 3. 三轮成本演算(两线同轨对照,输出相同不计入差值)

通用模型:每请求命中 = 前缀(上轮累计),未命中 = 增量;线性增长;无破坏前缀的操作。压缩请求一次付「未命中重建税」= 压后新内容 × 未命中价。

### 演算一(低点压缩,病态场景):20K 时压(压完 34K)vs 不压,各 145 请求爬到 180K

| | cache read | input(未命中) | 合计 |
|---|---|---|---|
| 压缩线 | 15.34M → ¥0.307 | 0.180M → ¥0.180 | **¥0.487** |
| 不压线 | 14.34M → ¥0.287 | 0.160M → ¥0.160 | **¥0.447** |

压缩线**贵 4 分(+9%)**:压完 34K 比不压的 20K 还大(过早压缩),纯经济小亏。教训:**压缩点过低时压缩无收益反有损**。

### 演算二(150K 高点压缩):T1 压(20K 系统区命中 + 42K 未命中 = 摘要 4K + ctx_status 8K + 活跃区 30K,起点 54K)vs T2 150K 继续爬,145 请求后各 +160K(T1→214K,T2→310K)

| | cache read | input | 合计 |
|---|---|---|---|
| T1 压缩 | 19.24M → ¥0.385 | 0.202M → ¥0.202 | **¥0.587** |
| T2 不压 | 33.19M → ¥0.664 | 0.160M → ¥0.160 | **¥0.824** |

**净省 ¥0.237(−21%)**。拆解:省全在 cache read 侧(−¥0.279),付的全在 input 全价侧(税 +¥0.042,其中 ctx_status 占 ¥0.008)。压缩线每请求平均 input 134K vs 230K。

### 演算三(第二段):T1 于 214K 二次压缩(起点 58K)vs T2 继续爬(310K→470K),各 145 请求 +160K

| | cache read | input | 合计 |
|---|---|---|---|
| T1 压缩 | 19.82M → ¥0.396 | 0.202M → ¥0.202 | **¥0.598** |
| T2 不压 | 56.39M → ¥1.128 | 0.160M → ¥0.160 | **¥1.288** |

**净省 ¥0.690(−54%)**。段均多省 ¥0.46:每段水位差固定拉大 160K,不压的成本是二次曲线。

### 结构性判据(四条单调性,第三轮修正后)

净差公式:**diff = (H₂−H₁)/r − 税**(H=累计命中量,r=价格比,税=压后新内容×未命中价×压缩次数)。

1. 价格比 r 越小 → ACP 越占优 ✓(r→1 全价兑现 input 总量差;**临界比 ≈602**(290 请求口径),超过后压缩转亏;DS Flash 50 距悬崖 12 倍)。
2. 活跃区越小 → 成本越占优 ✓,但它是唯一「双重惩罚」参数(加长命中前缀 + 按全价入税);其价值在性能(压后可见近期工作区),**成本最优 ≠ 整体最优**,保护区 min 语义卡平衡点。
3. 两次压缩间隔请求数越多 → 成本越占优 ✓(≈「高水位压缩更划算」的等价表述);但性能轴方向相反(段末水位高注意力先崩),经济许可 ≠ 该少压。
4. ~~每请求新增越少越占优~~ **反了**:步长越大 ACP 越占优(agent 吃上下文越凶压缩越值钱);步长→0 时 diff 收缩到只剩税。本仓实测增速 ≈1.1K/请求(245 会话中 58 个走完 20K→180K,均值 143 请求,中位 146),属温和区间。

### 会话增速实测(统计口径:assistant 块 = LLM 请求;上下文 = input+cacheRead+cacheWrite)

245 个会话:7 个从未到 20K,180 个到 20K 未到 180K,**58 个完成全程**;最小 29 / 最大 286 / 平均 143.0 / 中位 146;分箱众数 75–99。

## 4. 对照组也会压缩:优势缩水实验

新对照:T2 于 300K 触发全量压缩(摘要 30K 未命中 + 系统区 20K 命中 → 50K 起点),T1 维持主动压两次。

| 290 请求 | cache read | input | 合计 |
|---|---|---|---|
| T1 主动压两次 | 39.05M → ¥0.781 | 0.404M → ¥0.404 | **¥1.185** |
| T2 旧(永不压) | 89.58M → ¥1.792 | 0.320M → ¥0.320 | ¥2.112 |
| **T2 新(300K 触发一次)** | 51.12M → ¥1.022 | 0.350M → ¥0.350 | **¥1.372** |

- ACP 优势从 ¥0.93(−44%)缩水到 **¥0.19(−13.7%)**;分段拆解:第一段赢 ¥0.179(150K 早砸水位),第二段打平(¥0.008——T2 压后起点 50K 比 T1 的 58K 还低,且只交一次 30K 税 vs T1 两次 84K)。
- **结论:大头收益属于「会压缩」,不属于「压缩得早」**。触发线越接近 ACP 压缩点,差距趋零,胜负手移到税差与摘要质量。

## 5. 架构挑战:「300K 水位触发 L3 选块」替代主动层

- 经济轴成立:一次触发拿 ~80% 收益;L3 选块不增税;确定性/零引导成本/行为可预测。
- 性能前提未验证:**「300K 以内注意力保持良好」是外推不是事实**。论文最硬证据(256K 零强制触发下主动压仍 +9.2pp)出自激活 3B 的二线模型,256K 近其能力边界——用户正确指出该数字不能直接外推到 1M 前沿模型。
- 两种腐败机制须分开:检索失败型(大模型代际改善,RULER 类基准进步为证)vs 行为污染型(stale 假设竞争注意力、重复早期失败路径——与窗口大小不成比例,**前沿模型上无公开数据**)。「1M 模型 300K 内腐败轻微」与「腐败仍可观」都是合理先验 + 零证据。
- 水位触发的残留病灶:不看任务进度,可能压在阶段中间(L3 选块治「保什么」,不治「何时」)。

## 6. manifest 展示语义之辩(acp-runtime.ts `#refreshRoundStatus`)

**现状机制**:候选 = active zone − 保护 tail − status pairs;largest-first 资格排序 + 渲染预算截断(尾部豁免,「本轮豁免、下轮再列」);bN 编号即时间序(越大越新);每行 `bN | tokens | intent`;normal 压缩 fold 范围 = **manifest 列表 − keep,列表外一个不动**(豁免=安全,继续逐字在场);strong 压缩例外(整 zone 折叠,豁免块也折,保真靠摘要质量)。

**讨论走过的路**(保留推理路径,防止重蹈):

1. 「按时间倒序展示」(用户初案)——踩坑:截断砍尾会**饿死最老块**(老块持续垫底持续豁免,永远压不掉);largest-first 豁免小块则是暂态(大块压完自动获得资格)。
2. 「资格/展示分离」补丁——资格集 largest-first 选出,展示按时间倒序,头部注明 bN 时间序。约四行改动,未实施。
3. 「default=compress」提案(agent 未点名的块一律 fold,含未上榜块)——初始反对理由两条被用户技术性驳倒,记录修正:
   - ❌「agent 没见过豁免块」:错。豁免块在 active zone 逐字在场,compress 调用请求的 input 含其全文,摘要可覆盖。
   - ❌「unknown-unknowns,recall 失效」:降级。summary 带 per-block 索引行(bN+intent),fold 后是 known-unknowns。残余:索引行吃预算(fold 百块 = 百行),intent 质量决定「知道存在」能否升级为「想起要用」。
   - 修正后真实分歧仅三条:默认效应(keep 从主动拯救变例外抢救,keep 集系统性偏小);recall 往返经济学(误折代价 ∝ 块大小,recall = 往返 + 原文重新入 context);索引行预算压力。
   - 承认 default=compress 的架构优势:资格与展示彻底解耦,manifest 可纯按 keep 决策需要排(时间倒序畅通),分离补丁不再需要。
   - **关键现状重估**:现体系实为「按块大小分段采用 default=compress」——上榜大块本来未 keep 即 fold(从严),豁免小块 default=safe(从宽);而 recall 经济学(误折代价 ∝ 块大小)恰好令风险等级与块大小对齐。提案等于把 compress 默认推广到小块,用 recall 网兜底换 zone 每轮清空。
4. 未决,交 P3 消融裁决(见 §7)。

**成本语义备忘**(讨论中钉死、易被遗忘的事实):只有 manifest 列表内 UNKEPT 块会被 fold;context_status「大」是买完整决策空间,有渲染预算上界 + `enforceInlineByteCap` artifact 兜底;v10 pull 模式(不压缩轮次零注入)令这份成本只在压缩轮次发生。

## 7. P3 消融实验设计(裁决以上全部争论)

四臂(同引擎同任务,只翻被测开关):

| 臂 | 配置 | 检验的命题 |
|---|---|---|
| 1 | ACP 现状(主动引导 + default=safe 豁免) | 基线 |
| 2 | 跳过 L1/L2,300K 水位触发 L3 强制 | 主动层价值 / 用户简化案 |
| 3 | 关 ACP,全历史 | 腐败是否存在 |
| 4 | default=compress(fold 全候选 − keep) | 压缩默认动作翻转 |

- **任务集**:起步自建——oh-my-pi / omp-desktop 历史 issue,检出修复前 commit + `.git` 挪走(防偷看 log),验收 = 该 commit 引入的测试(全自动)。SWE-bench 子集为第二轮升级项(需 docker 评测设施)。**先筛选:基线(臂 3)轨迹 ≥100 请求的任务才入对比集**,否则压不压无差别。
- **指标**:终点 = 测试通过率(裁决);过程 = recall 次数与时机、keep 集大小、重复探索率(同文件重读/同命令重跑/回已否决方案)、每任务成本,**全部按发生时水位分桶 → 腐败曲线**(重复探索率 vs 水位:平 = 1M 模型短水位无腐败支持臂 2,爬升 = 腐败真实)。
- **样本量与成本**:先 40 任务/臂单次看方向(四臂 ≈160 次运行,外推几十至几百元),要分辨 10pp 需 80–100/臂;开跑前 3 任务试跑报实数。
- **判读规则(预注册,防事后归因)**:臂 4 recall↑ 而成功率不降 → 采纳臂 4;降 → default=safe 保住。臂 2 ≈ 臂 1 → 主动层简化为水位触发;臂 1 胜 → 下钻腐败曲线找赢在哪个水位段。臂 3 垫底且腐败曲线平 → 主动层整个该砍(接受此结局)。
- **先行步骤**:应用内冒烟(`OMP_PROFILE=omp-desktop-test` + 长任务)先验机制与体验,jsonl 事后解析行为对比;批量放闲时队列。**阻塞项:用户在 OMP 端的新实现之仓库/分支/开关方式未提供。**
